### 1. HIGH — a category pick is displayed but silently discarded

`src/app/pages/library/book/book-detail/book-detail.component.ts:325`

`onCategoryPicked` bails out with `if (!ctgy) return;` after the inner tree-select has already displayed the
picked node, so the pick is silently dropped instead of being surfaced or reverted.

**Failure scenario:** the `BookCategories` cache is stale or empty (e.g. the home changed mid-flight —
`fetchAllBookCategories()` only writes the cache when `this._currentHomeID() === reqHomeID` — or a category
was created after the page loaded). The user picks "Novel" in the inline category tree: `onPick` sets the
wrapper's internal `_value` and the dropdown/trigger renders "Novel", but the parent row object is never
replaced, so `data.ID` stays 0. Because the bound expression `data.ID > 0 ? ... : null` never changes,
NgModel never calls `writeValue`, and the control keeps showing "Novel" while the model is still blank. On
save, `onSave` drops every row with `ID <= 0`, so the category the user saw selected is silently discarded
with no error and no console warning.

### 2. MEDIUM — wrapped tree-select can never become `touched` from focus-then-leave

`src/app/shared/trantype-tree-select/trantype-tree-select.component.ts:118` (same defect in
`controlcenter-tree-select.component.ts:101`)

`_fnTouched` is only invoked inside `onPick`, never on blur, so a tree-select field wrapped by this CVA can
never become `touched` from focus-then-leave.

**Failure scenario:** regression versus the raw `nz-select` these 16 templates previously used (`nz-select`'s
own CVA fires `onTouched` on blur). In an `nz-form-control nzHasFeedback [nzErrorTip]` block for a required
tran type / control center, the user clicks into the field, decides not to change it, and clicks away —
`touched` stays false, so the validation error tip never renders even though the control is invalid and
visibly empty. Worse, the reverse case: the user opens the dropdown and clears the value with the new
(now always-present) clear button; `onPick` does fire touched there, but any site where the value is emptied
programmatically or by clicking outside leaves the form untouched-but-invalid, and submit-time error
reporting depends on whether the page happens to call `markAllAsTouched()`.

### 3. MEDIUM — `.detail-cell` ellipsis clamp cannot take effect

`src/app/pages/library/book/book-list/book-list.component.less:10`

`.detail-cell` relies on `max-width` + `overflow`/`text-overflow`, but the host `nz-table` has neither
`nzScroll` nor `nzTableLayout="fixed"`, so auto table layout ignores the clamp — the comment claims a
guarantee the CSS cannot deliver.

**Failure scenario:** a book is saved with a 200-character Detail note (the field's `maxLength` allows
exactly this). With `table-layout: auto`, the browser sizes the column to the cell's max-content width and
`max-width` on a `<td>` is not honoured, so the Detail column expands and squeezes/pushes the ISBN, year,
page-count, copy-count and audit-date columns; the list becomes horizontally distorted and the ellipsis
never appears, defeating the whole purpose of the `.detail-cell` rule (the `[title]` tooltip on line 126 is
then the only way to read the value, while the text is still fully laid out).

### 4. MEDIUM — finance i18n key on a library action

`src/app/pages/library/book/book-associations/book-associations.component.html:81`

The library "add a category row" button reuses the finance-scoped key `Finance.CreateItem` (replacing
`Library.SelectCategory`), so a finance term labels a library action.

**Failure scenario:** on the book associations page an English user sees "Create an item" next to the
category table — with no hint that it appends a blank category row to assign below; a Chinese user sees the
finance wording 新建行项目. The bug is latent and outward-facing: when someone later rewords the finance
create-item string for an unrelated invoice/plan change, the library page's button text silently changes
too, and vice versa. It also breaks the i18n convention that a key's prefix names the feature that owns the
string.

### 5. MEDIUM — category tree does not follow a language switch

`src/app/pages/library/book/book-detail/book-detail.component.ts:352`

`_buildCategoryTree` snapshots the language with an imperative `translate(val.Name)` at build time, while
sibling category consumers re-derive on language change.

**Failure scenario:** the user opens a book detail page (tree built with the current language, e.g. Chinese
titles), then switches the UI language to English via the header switcher. `categoryTree` is a plain signal
set once in `ngOnInit` (lines 172/220) and is never rebuilt, so the inline category tree and its dropdown
keep showing the previous language's category names — while `book-list`'s equivalent tree refreshes because
it re-derives on its `langTick`. The same stale-language mismatch shows up for any category whose translated
name differs between the two languages, and the user has no way to force a rebuild short of reloading the
page.

### 6. LOW — tree assembly triplicated, copies already drifted

`src/app/shared/controlcenter-tree-select/controlcenter-tree-select.component.ts:79`

The parent/child tree assembly (`_buildTree` / `_buildCategoryTree`) is now triplicated — here, in
`trantype-tree-select.component.ts`, and in `book-detail.component.ts` — each re-deriving dotted paths that
the services already expose as `FullDisplayText`.

**Failure scenario:** both new wrappers rebuild the hierarchy from the flat dictionary and hoist orphans, and
`book-detail` does the same for `BookCategory`, while `FinanceOdataService.buildTranTypeHierarchy` and
`LibraryStorageService._buildBookCategoryHierarchy` already materialise the same structure and
`TranType.FullDisplayText`/`BookCategory.FullDisplayText` already contain the joined path the components
recompute in `displayWith`. The three copies have already drifted in root detection
(`(val.ParId || null) === parentId` vs. the `!value.ParId` convention elsewhere) and in the wrapper's orphan
handling; fixing a real case — a self-referencing parent, or a cycle — requires the same edit in three
files, and missing one makes the same dictionary render a different tree (and a different selectable set)
in the tran-type picker than in the control-center picker.

### 7. LOW — converted fields silently became clearable

`src/app/shared/trantype-tree-select/trantype-tree-select.component.ts:45`

The wrapper exposes no `nzAllowClear` input, and `nz-tree-select` defaults `nzAllowClear` to true while the
`nz-select` it replaced defaults it to false — every converted field silently became clearable.

**Failure scenario:** sites that deliberately omitted `nzAllowClear` on the old `nz-select`
(control-center-detail's parent, plan-detail's tran type and control center, document-items' tran type) now
render a clear (x) affordance. A user who clicks it clears a field that the previous UI gave them no way to
empty; the component then emits `undefined` through ngModel and, on submit, a PUT body that omits/empties the
value can null the column via `_context.Entry(existing).CurrentValues.SetValues(update)`. There is no way
for a caller to restore the old behaviour short of editing the wrapper.
