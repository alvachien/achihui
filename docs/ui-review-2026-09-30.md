### 1. MEDIUM — a stale in-flight query response overwrites the current analysis

`src/app/pages/finance/document/document-item-insight/document-item-insight.component.ts:557`

The closeable criteria tags are rendered synchronously in `ngOnInit` (the `@if (insightOption())` block
binds the signal set on line 486), while the initial row load runs asynchronously
(`forkJoin(metadata) → fetchData()`). Before this change `fetchData()` was called exactly once, so no two
queries could overlap. Now it is also user-triggerable via `onRemoveDirection()`/`onRemoveExcludeTransfer()`
while the first load is still in flight. Two `searchDocItem` queries with **different** server filters can
then be live at once (e.g. the initial `IsExpense`-filtered query and the broader direction-removed query),
and `next` applied unconditionally — so whichever response arrived **last** won, not whichever was newest.

**Failure scenario:** user opens the insight with a direction filter, then closes the direction tag before
the first page resolves. The broader query (no `IsExpense` filter) resolves first and fills the KPIs with
income+outgo; the stale narrower query resolves a moment later and overwrites `listData` with income-only
rows. The income/outgo/net cards and both charts then show wrong totals with no error, persisting until the
next interaction. For a finance surface, silently-wrong aggregates are the impact that raises this above LOW.

**Fix:** a `fetchGeneration` counter bumped at the top of each `fetchData()`; the response handlers ignore any
result whose captured generation is no longer current (see Fix status #1). This is the same "latest request
wins" guard the tree-select `onCategoryPicked` fix (2026-09-20 review, finding 1) applied to a different race.

### 2. LOW — needless refetch when dropping the exclude-transfer criterion

`src/app/pages/finance/document/document-item-insight/document-item-insight.component.ts:548`

`ExcludeTransfer` is applied only in `buildDisplayList()` (client-side `isTransferTranType` filter); it is
never added to the `GeneralFilterItem[]` sent to `searchDocItem`. So closing its tag does not change the
server query — the rows already in `listData` are complete. The original handler called `fetchData()` anyway,
paying a redundant round-trip and (pre-#1) widening the overlap window. Now it calls `buildDisplayList()`.

### 3. LOW — missing regression guard for the descriptions fix in two of three flows

The `nz-descriptions` nested-in-`<div>` items-dropped defect (fixed in this diff for all three create flows)
had a teeth-checked regression guard only in `document-normal-mass-create.component.spec.ts`. Added the
equivalent guard to `document-recurred-mass-create`. `document-loan-repay-create` deferred — see Fix status #3.
