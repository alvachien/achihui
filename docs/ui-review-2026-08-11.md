# H.I.H. UI Review — 2026-08-11

A code-quality review of the `achihui` Angular 21 + NG-ZORRO 21 front end, covering
runtime correctness (zoneless/signals/RxJS), TypeScript & Angular hygiene, dead code /
duplication, build/config, and security. Findings are severity-ranked and verified by
reading the actual code. Blog (`pages/blog`) and Event (`pages/event`) features are
temporarily shut down (routes commented out) — they are reviewed here because the
shutdown is documented as reversible.

## High

### 1. RxJS subscription leaks in active finance/library delete & save paths
Several handlers subscribe without `takeUntil` / `takeUntilDestroyed` despite
`destroyedRef` / `_destroyed$` being available and used elsewhere in the same component.
If the component/dialog closes before the HTTP completes, the `next` handler runs against
a destroyed view.

- `src/app/pages/finance/finance.component.ts:218` — `forkJoin` in `onAssetDeprec`
- `src/app/pages/finance/finance.component.ts:551` — `createDoc` inside the depreciation dialog
- `src/app/pages/finance/document/document-list/document-list.component.ts:415` — `deleteDocument`
- `src/app/pages/finance/document/document-list/document-list.component.ts:456,472` — `modal.afterClose` → `fetchData`
- `src/app/pages/library/book/book-list/book-list.component.ts:171` — `deleteBook`
- Same delete-handler pattern: `library/person/person-list`, `library/organization/organization-list`,
  `library/location/location-list`, `library/borrow-record-list` (live top-level copy only)

### 2. Pervasive untyped service layer (~1,600 `any` values)
`src/common/any.ts:2` defines `SafeAny = any` and it is used 1,119 times specifically to
bypass the `no-explicit-any` lint rule. Worst at the service API boundary — public
properties typed `any` (URL strings as `any` in `library-storage.service.ts:69-75`) and
return types `Observable<any>` (`home-def-odata.service.ts:311,337,371,414,457`,
`library-storage.service.ts:438,606,778,954,1083`, `finance-storage.service.ts:48`,
`tags.service.ts:24`). OData responses are effectively untyped end-to-end.

### 3. `MarkdownEditorComponent.value` getter writes a signal as a side-effect
`src/app/pages/reusable-components/markdown-editor/markdown-editor.component.ts:100-110`
calls `this.content.set(...)` inside the getter. In a zoneless app, reading this getter
from a template or `computed`/`effect` can throw `NG0600` or cause a change-detection loop.

## Medium

### 4. Markdown rendered with no sanitization (stored-XSS gap) - VERIFIED: false positive
**Verification (2026-08-11):** `ngx-markdown` applies its OWN sanitization independent of
`marked` - `MarkdownService.parse()` calls `sanitizeHtml()`, which defaults to
`DomSanitizer.sanitize(SecurityContext.HTML, html)` (Angular's built-in HTML sanitizer;
strips scripts / event handlers / `javascript:` URLs). It is active by default unless
`disableSanitizer` is set or `sanitize: SecurityContext.NONE` is configured, and a grep of
`src/` confirms the app sets neither. No `[innerHTML]` / `bypassSecurityTrust` bypasses
exist. **No action needed** - adding DOMPurify would be redundant. The original text below
described the initial (incorrect) concern:

`reusable-components.module.ts:28` (since deleted) configured `MarkdownModule.forChild()`
with no explicit sanitization; `ngx-markdown` renders via `marked` v18, which dropped its
built-in sanitizer. User-authored markdown flows to `innerHTML`. Mitigated today by OIDC
auth + the Blog shutdown - **must be fixed before Blog is re-enabled** (add DOMPurify-based
sanitization).
`reusable-components.module.ts:28` configures `MarkdownModule.forChild()` with no
sanitization; `ngx-markdown` renders via `marked` v18, which dropped its built-in
sanitizer. User-authored markdown flows to `innerHTML`. Mitigated today by OIDC auth +

### 5. Dormant Blog/Event features will break on re-enable
Across all blog + event components:
- `isLoadingResults` is a plain boolean set to `false` in `finalize()` with no
  `markForCheck()` — in zoneless mode the loading spinner won't clear.
- `activateRoute.url.subscribe(...)` lacks `takeUntil` (`post-detail.component.ts:105`,
  `collection-detail.component.ts:68`, event detail components).
- Deploy/delete handlers subscribe without cleanup (`post-detail.component.ts:303,368`,
  `post-list.component.ts:146,166`, `user-setting.component.ts:150`,
  `normal-event-list.component.ts:133,154`, `recur-event-detail.component.ts:191`).

The correct pattern (`takeUntilDestroyed(this.destroyedRef)`) already exists in
`home-def-detail.component.ts:151`.

### 6. `marked` is double-loaded
`angular.json:67` loads `marked/lib/marked.umd.js` as a global script, but `ngx-markdown`
already bundles `marked` as an ES module import (it is a peerDependency). No code
references a global `marked`. Remove the entry — pure bundle bloat + version-drift risk.
(The `katex` UMD entries on `:68-69` ARE needed — keep those.)

### 7. 16 dead duplicate folders from an incomplete refactor
Verified live-vs-dead against each `*.routes.ts`:
- **Blog** (nested dead): `blog/post/{post-list,post-detail}`, `blog/collection/{collection-list,collection-detail}`
- **Event** (nested dead): `event/normal-event/{normal-event-list,normal-event-detail}`, `event/recur-event/{recur-event-list,recur-event-detail}`
- **Library** (nested dead): `library/borrow-record/{borrow-record-list,borrow-record-create-dlg}`; plus dead `library/{person,location,organization}/*-selection-dlg` (top-level ones are live)
- **Finance — inverted** (top-level dead): `finance/document-item-{search,view,insight}` (live copies are under `finance/document/`)
- `finance/account-settle-dialog` vs `finance/account/account-settle-dialog` — both are empty stubs, both dead

Each dead folder carries its own `.component.ts` + `.spec.ts`, so duplication also inflates the test suite.

### 8. Five dead `*-ui.module.ts` NgModules + two dead services
`finance-ui.module.ts`, `library-ui.module.ts`, `blog-ui.module.ts`, `event-ui.module.ts`,
`reusable-components.module.ts` are barrel re-export modules referenced **only by spec
files** — no route or production code imports them (the app boots standalone).
`services/tags.service.ts` and `services/finance-storage.service.ts` are `@Injectable()`
with no `providedIn` and no production injection (only their own specs import them).
Removing the dead folders in #7 makes `event-ui.module.ts` fully unreferenced.

### 9. ~200+ `no-non-null-assertion` + 6 `no-unsafe-optional-chaining` suppressions
Concentrated in `markdown-editor.component.ts` (30+), `blog/post-detail` (30+, dormant),
`finance.component.ts` (15+). Volume makes it impossible to distinguish safe `!`
assertions from real null-pointer bugs; the 6 optional-chaining suppressions (in
`recur-event-detail`, `normal-event-detail`, `borrow-record-create-dlg`, `account-report`)
could mask runtime errors.

## Low / hygiene

- **`vitest.config.ts` is redundant.** `npm test` → `ng test` → `@angular/build:unit-test`,
  which runs Vitest under the hood (confirmed: `tsconfig.spec.json` uses `vitest/globals`,
  specs import `{ vi } from 'vitest'`). The root `vitest.config.ts` is not referenced by
  `angular.json` and no script invokes `vitest` directly. Path aliases match — no coverage
  gap, just a stale entry point.
- **`zone.js` still in `angular.json` polyfills** despite zoneless — intentional/transitional
  per the migration notes (zero `NgZone` usages in app code). Leave for now; removable once
  NG-ZORRO/ECharts zoneless compatibility is confirmed.
- **Stray unguarded `console.log`**: `app.config.ts:51` (`'Entering App Initializer...'` —
  runs every startup), `finance/account/account-hierarchy.component.ts:227`, plus
  `modal.afterOpen/afterClose` logging in ~9 components. (`ModelUtility.writeConsoleLog`
  debug calls are gated and fine.)
- **Redundant `changeDetect.detectChanges()`** at `markdown-editor.component.ts:208` —
  called right after `content.set(...)`, which already schedules CD in zoneless.
- **`control-center-hierarchy.component.ts:116`** mutates a plain `col` number inside
  `requestAnimationFrame` and calls `detectChanges()` — works, but `col` should be a signal.
- **Unused barrel** `src/app/pages/event/index.ts`.
- **~25 `no-unused-vars` suppressions** suggesting dead event-handler parameters.

## Verified clean
No `@ts-ignore` / `@ts-expect-error`; no `TODO` / `FIXME` / `HACK` markers; no swallowed
errors (all `catchError` blocks log + rethrow); no deprecated Angular APIs; no hardcoded
API/localhost URLs outside `environments/`; all `effect()`s are in injection contexts with
no async/signal-write misuse; all `toSignal` / `toObservable` calls are in field
initializers; auth interceptor correctly scopes the bearer token to `environment.ApiUrl`
only; no `[innerHTML]` / `bypassSecurityTrust` bypasses in code (the only HTML injection
surface is `ngx-markdown` itself, per #4).
